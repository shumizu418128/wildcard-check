evaluate までの処理経路

GenVisibility.evaluate を名前で呼んでいる箇所はない。 RunReviews.execute が catalog のルールを上から見て、 applies が True のオブジェクトに rule.evaluate を呼ぶ。 GenVisibility はその 2 番目。

1. 呼び出しの順番

橙の矢印だけが evaluate。 起動時に catalog.rules を渡した RunReviews が、レスポンスを返したあとに動く。

9 の GET は画面の Next（pollReview）から。 GetReview が保存済みの bool を返す。矢印は controller で止まる。 evaluate は同期関数なので、6 は asyncio.to_thread 経由。

2. video が bytes になる場所

video は全ルール共通の第2引数で、中身はアップロードしたファイル。 YouTube の URL は Review.youtube_url に文字列で入る。 YouTube 提出では第2引数はどのルールでも None。

本番で rule.evaluate を書いているのは backend/app/usecase/run_reviews.py のこの行。 テストの backend/tests/test_reviews.py は未実装確認のため evaluate を直接呼ぶ。 

ok = await asyncio.to_thread(
    rule.evaluate, review, review_input.video, self.judge
)
